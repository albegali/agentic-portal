# Analyzer framework

## User Story

As a portal server, I want a finding model and adapters that call analyzers present on PATH or read their report files, so that insight screens share one pipeline and a missing scanner is reported, not fatal.

## Description

- Epic: EP-05 — Codebase health
- Priority (MoSCoW): Should · Release: R2 · Size: L · Type: technical
- Requirements: FR-22, NFR-08
- Depends on: AP0104, AP0108
- Notes: ADR-007; analyzers chosen per stack from /architecture.
- Out of scope: Specific insight screens.

## Acceptance Criteria

- Given an analyzer not installed, when the scan runs, then the missing tool is reported and other analyzers continue.
- Given a recorded SARIF/JSON output, when it is parsed, then findings with severity, location and source analyzer are stored in .portal/findings.json.
- Given an installed analyzer, when it exits non-zero or times out, then the failure is reported, not fatal.
