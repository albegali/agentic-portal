# Upstream: launcher delivers the session token

## User Story

As a portal (consumer of agentic-skeleton), I want tools/portal.py to generate the session token, store it in a user-only file in .portal/, pass it to the server as PORTAL_TOKEN and open the URL with #token=…, so that the browser authenticates on first open and a reused running portal opens the same session.

## Acceptance Criteria

- Given `make portal` starting a portal, when the browser opens, then the URL carries the token in the fragment and the server accepts it.
- Given the token file in .portal/, when I inspect its permissions, then only the current user can read it (0600; icacls on Windows, warning if it fails).
- Given a portal already running for the repo, when I run `make portal` again, then the running one opens with the same token read from the file.
